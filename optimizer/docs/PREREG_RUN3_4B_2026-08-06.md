# Pre-registration — Run 3: the research pipeline on the 4B, judged by the 35B

**Written and committed BEFORE any arm was executed.** 2026-08-06.

## The decision this informs

Should `RESEARCH_LEDGER` be flipped **on by default**? Run 2 said no on a ~30B model and named four
defects; those are fixed (`64f8c8c`, `add34a0`). This round asks the same question on the *hardest*
target in the fleet and with a judge that has no stake in the design.

## Arms

- **A = today's shipping default.** `RESEARCH_LEDGER` unset. The `research_note` tool is absent.
- **B = the flag on.** `research_note`, the page cache, budget footer, wrap-steer, ledger.

Both arms otherwise identical: same model, same skill text, same live web, same harness commit.

**Subject:** `qwopus35-4b` via llama-swap on `:8080`.
**Judge:** `qwen36-35b-iq3s`, same box, via `judge.py` with `FRONTIER_BASE_URL` set to the local
llama-swap endpoint and `FRONTIER_MODEL=qwen36-35b-iq3s`. No code change — `judge.py` already takes
any OpenAI-compatible endpoint. (Endpoint URLs are kept out of this file: the repo is public and
the secret scanner treats a literal endpoint as a finding.)

Single-slot discipline: all 10 subject sessions run first and sequentially, then one model swap, then
all judging. No concurrent requests.

## Questions (5, spread across the modes, from the pre-existing set of 10)

| # | Question | Mode | Why |
|---|---|---|---|
| Q2 | License of the `ketch` CLI | current-fact | ground truth known (MIT) — the calibrator |
| Q8 | Is llama.cpp GBNF nested-string `maxLength` (#25746) open or fixed? | freshness | ground truth known (Open) and gradable |
| Q9 | Exact measured decode throughput of Maple-Preview 20B on an M3 Pro | **adversarial** | likely unfindable — tests fabrication vs honest "not found" |
| Q6 | MLX vs llama.cpp for tool-calling agents on Apple Silicon | comparative | multi-source synthesis |
| Q4 | Is RAG still necessary in 2026, or have long-context models displaced it? | contested | must attribute both positions |

## Outcome measures, fixed in advance

**Primary — deterministic, no judge:**
1. notes recorded / rejected, and the `reason_class` breakdown across all six values.
2. ledger present, and count of `- attributed-to:` lines (auto-corrections — the metric that says
   whether Fix 1 did its job; Run 2's refusals should appear here as successes instead).
3. **Wall-clock seconds per session, per arm.** New, and deliberate: this is the C-cost dimension
   recorded 2026-08-06. A same-quality arm that costs materially more is a regression the old
   instrument could not see. The probe already suggests a real delta (A 1:29 vs B 2:11 on Q2).

**Secondary — soft:** 35B pairwise judge, order randomized per question, malformed→tie, rubric =
correctness, clarity, concision, **and citation fidelity** (every material claim traceable to a
quoted source; penalize uncited or unsupported claims).

**Honesty (Q9 only), graded by hand against the transcript:** an arm that states a specific
throughput number without a source is a **fail** regardless of what the judge says.

## Adoption rule, fixed in advance

Flip the default **only if** B wins-or-ties the judge **and** B's citation fidelity is strictly
better **and** the cost delta is defensible. Any other combination → stays dark. A tie on the judge
with better fidelity and a large cost delta is **not** an adoption.

## Declared limitations — read before believing any verdict here

1. **The judge is a 35B and is uncalibrated.** Judge-rubric calibration has been an open task
   (#12) since before this round. It is weaker than a frontier judge and may not discriminate
   finely. It is, however, *disinterested* — which Run 2's judge (me, the designer) was not. This
   round trades judge capability for judge independence, deliberately.
2. **n = 1 per cell.** 5 questions × 2 arms, no repeats. Exploratory; cannot establish a small
   effect and is not a gate round.
3. **Live web.** Sources may change between arms. Mitigation: arms run back-to-back per question.
4. **The subject is a 4B.** Results do not transfer to the 35B of Run 2. This answers "does the
   pipeline help the hardest target", a different question from Run 2's.
5. **Known confound, measured at zero on this model:** skill v2 ships always-on and instructs the
   model to call `research_note` in four places, but arm A does not have that tool. A probe
   confirmed the 4B silently ignores the instruction — no error, no retry loop. The ungated text is
   a latent defect (dead context, and a different model might loop on it) filed separately; it does
   not invalidate arm A here.

# RESULTS — 2026-08-06 (10 sessions, `qwopus35-4b`, judged by `qwen36-35b-iq3s`)

## Verdict against the pre-registered adoption rule: NO ADOPTION. `RESEARCH_LEDGER` stays dark.

The rule required B to win-or-tie the judge **and** show strictly better fidelity **and** a
defensible cost. B failed the first and third outright.

## The finding of the round: the refusal storm aborts the session

Two arm-B sessions produced **no answer at all** — zero bytes, `Request aborted`. The cause is a
composition of two individually reasonable mechanisms:

> `research_note` refuses a quote → the model retries → repeated failing tool outcomes →
> `loop-breaker` escalates tier 1 → 2 → 3 → **abort** → the deliverable is destroyed.

| B session | refusals | loop-breaker aborts | answer |
|---|---|---|---|
| Q2-B | 0 | 0 | ok |
| Q8-B | 5 | 0 | ok |
| **Q9-B** | **11** | **1** | **none (aborted)** |
| **Q6-B** | **12** | **1** | **none (aborted)** |
| Q4-B | 4 | 0 | ok |

Arm A aborted zero times and answered all five. **Turning the pipeline on cost 40% of the
deliverables.** Run 2 called the refusal storm a quality and cost problem; on a smaller model it is
an availability problem. That is a strictly worse class of failure and it was invisible to every
instrument we had until wall-clock and answer-length were recorded.

## Fix 1 repaired the 35B's failure mode; the 4B has a different one

| reason_class | count | |
|---|---|---|
| `quote_not_found` | 25 | the model **paraphrased** instead of copying |
| `url_not_read` | 7 | cited a page it never fetched |
| `corrected` | 2 | wrong-URL attribution — *the case Fix 1 targets* |
| `ok` | 13 | |

Refusal rate **68%** (Run 2 on the 35B: 62%) — no better, slightly worse. Run 2's refusals were
dominated by wrong-URL attribution, and Fix 1 addresses exactly that; it fired **twice**. The 4B
does not make that mistake. It makes a different one: it paraphrases, and no auto-correction can
rescue a quote that was never in any page. **The fix was correct for the model it was measured on
and largely irrelevant one tier down.** This is the clearest instance yet of the standing rule that
a harness result does not transfer across models — recorded here against my own work.

## Fix 3 (the wrap-steer) is now suspect

It fired in exactly the three sessions with ≥5 refusals, including both that aborted. By design it
fires when a session reaches wrap-up with reads but no notes — i.e. **only on struggling sessions**
— and it injects a message that re-enters the agent loop, adding a turn. It therefore adds
loop-breaker pressure precisely where pressure is already lethal. Not proven causal (the refusals
alone plausibly suffice), but its benefit is unmeasured and its risk is now visible. It should not
ship on until a round separates the two.

## Cost (the C-cost dimension, recorded this morning, first use)

arm A 1342s total / 268s mean · arm B 1993s total / 399s mean · **B/A = 1.49×**

Per question: Q2 +8%, Q8 +82%, Q9 +260%, Q6 +68%, Q4 **−52%** (B aborted early paths). The overhead
is not uniform — it is near-zero on a one-source lookup and explodes on questions with no findable
answer, because the pipeline demands a verbatim quote and an unfindable fact yields none. **The
pipeline spends most where it can gain least.** Recording cost was decided before the round and
earned its place in the first outing: it is what surfaced the zero-length answers.

## Judge (secondary, weak by design)

| | primary (pre-registered, randomized order) | both-orders check |
|---|---|---|
| Q2 | A | inconsistent (AB→B, BA→A) — position bias, no signal |
| Q8 | A | B, B — contradicts the primary; judge is non-deterministic |
| Q4 | A | A, A — consistent |
| Q9, Q6 | **SKIP** — arm B produced no answer to judge | |

**A 3 / B 0 / 2 unjudgeable.** Only Q4 is robust. The 35B judge is noisy exactly as pre-registered,
so treat the tally as weak corroboration of the deterministic result, not as the result.

## Q9 honesty: both arms fail, in opposite directions

- **Arm A fabricated.** It stated `30.52 tok/s` (and `218 tok/s`) for Maple-Preview 20B on an M3
  Pro with no hedge and no source — precisely the failure the pipeline exists to prevent.
- **Arm B did not fabricate — because it never answered.** It aborted.

The pipeline prevented the fabrication by preventing the deliverable. That is a real property, and
it is not a win.

## What this changes

1. `RESEARCH_LEDGER` stays **dark**, now on stronger evidence than Run 2's.
2. **The refusal→abort composition is the thing to fix before anything else.** Options, unbuilt:
   cap consecutive `research_note` refusals per session and degrade to "cite inline, mark
   `[unverified]`"; or make refusals not count as failing outcomes to the loop-breaker; or both.
   Until one exists, the pipeline is unsafe to enable on any model that paraphrases.
3. Fix 3 does not ship on before its benefit is separated from its risk.
4. `quote_not_found` at 25/32 says the binding constraint is **getting a small model to copy rather
   than paraphrase** — a prompt/mechanism problem upstream of everything the ledger does.
