## Contract and inventory

`pi-munchkin/continuation-request/v1` is the only automatic provider-turn
request channel. A request contains a hashed Pi session identity, hashed owner
identity, durable owner generation, scope, reason, priority, idempotency key,
bounded message, and expiry. The producer supplies a last-moment authorization
callback that rereads its durable state. `control-arbiter.ts` is the sole
dispatcher: it holds offers while an agent run is active, waits for Pi's real
`agent_settled` event, picks at most one priority winner, reauthorizes it, writes
an idempotent receipt, then starts a fresh idle Pi turn. It never writes Pi's
private follow-up queue.

| Producer | Previous scheduling point | Authority owner and durable generation |
|---|---|---|
| Persistent goal | `agent_end` custom follow-up | current executable goal ID and full persisted revision |
| Deep-research parent synthesis | child-result merge after parent turn | plan run ID and terminal-head marker |
| Citation correction | terminal research answer | current goal revision, or stable answer digest for a goal-free session |
| Context handoff | compaction completion | current goal revision, or serving-epoch handoff generation |
| Explicit compaction resume | compaction completion/error | current goal revision, or compaction token generation |
| Drift review advisory | detached review completion | session identity, commit-head owner, and review generation |

The complete first-party scheduling inventory also includes the corrective and
recovery paths that do not create an autonomous continuation under the shipped
arbiter:

| Producer | Lifecycle hook | Queue/ownership contract |
|---|---|---|
| Loop breaker (outcome, semantic, and session-repeat corrections) | `turn_end` after outcome/episode accounting | Emits a typed control proposal. `control-arbiter` owns delivery; the direct `sendUserMessage(..., deliverAs="steer")` is retained only as the explicit `CONTROL_ARBITER=off` rollback. Tier-three abort/shutdown invokes Pi's supported signal and never queues work. |
| Tool-call rescue | `turn_end` after pseudo-call detection | Same proposal/charge path and legacy-only steer fallback; no follow-up queue when enforce is active. |
| Verify gate | `turn_end` wrap-up after mutation/verification state update | Same proposal/charge path and legacy-only steer fallback; the warning at `agent_end` is notification-only. |
| Research wrap-up hint | `turn_end` after reads with no verified notes | Same proposal/charge path and legacy-only steer fallback; citation correction is a typed continuation offer and is reauthorized against the goal/answer generation. |
| Session blackboard lens | `turn_end` after a higher-priority failure proposal | Same proposal/charge path and legacy-only steer fallback; it is a bounded context hint, not an autonomous retry. |
| Manual loop/recovery command | user command/domain recovery signal | `sendMessage(triggerTurn=true)` or a non-triggering `nextTurn` recovery brief is explicitly user-owned; it is not an automatic producer. |

Interactive `/goal`, `/goal-resume`, and `/plan` commands are user actions, not
automatic continuations. The control arbiter's existing same-turn corrective
steers and abort/shutdown effects remain their own Pi-supported operations; an
abort or shutdown is terminal and does not create a continuation. Manual
run-capsule recovery remains context restoration rather than an automatic model
turn. The detached drift reviewer is also migrated: its advisory is now an
authority offer bound to the reviewed commit and session generation. There is no
first-party direct automatic `followUp` left in the migrated producer paths.

The cancellation boundary is precise: after a pause, block, cancel,
replacement, or settlement has committed, an earlier offer can exist in memory
but its authorization reread fails at `agent_settled`, before a new provider
request. An already executing request is not retroactively claimed to be
undone. Expiry, session hash, owner generation, and durable receipts make late
callbacks, duplicate emission, and extension reloads fail closed.

## Offline evidence

The no-network `AgentSession` fixture uses Pi's real extension runtime and a
scripted provider while counting actual provider requests and
`tool_execution_start` events. It proves one initial request only after pause,
block, cancel, full settlement, 80/20 settlement, and goal replacement; it
proves two separately settled requests for an unchanged active goal; and it
proves the original user message reaches the provider. A deterministic tool-call
turn proves the execution counter is attached to Pi's real lifecycle rather than
to a test-only callback. It also verifies that no obsolete private follow-up
remains queued.

The same fixture now drives Pi's actual `compact_context` tool with a
deterministic `session_before_compact` handler (no network or summarizer call).
Pi persists a real extension-provided compaction entry and emits its real
compaction lifecycle. With an active goal, exactly one authority-approved
post-compaction provider turn runs and the executable goal remains active. With
a paused goal, compaction still completes but produces no continuation and no
hidden third provider request; the paused status remains authoritative.

A separate recovery case then constructs a fresh `AgentSession` and extension
runtime after that compaction. The new session reads the private ledger and its
first real provider payload contains the complete objective and required
criterion. The fixture uses Pi coding-agent's production `convertToLlm`
transformer, so the assertion covers the actual custom-message-to-LLM contract
rather than Agent core's low-level default converter.

The compact-tool and plan-graph fixtures now assert authority offers rather
than direct custom follow-ups. The arbiter unit fixture asserts that offers are
held while active, dispatched only after settlement, and rejected when authority
changes before that boundary. It also proves deterministic priority selection
for competing offers, skips a stale high-priority offer in favor of a valid
lower-priority one, and uses receipt-backed duplicate suppression across a
reload.
Existing plan-runner regression coverage verifies one offer per unchanged goal
revision and preserves user text that merely resembles a harness prefix.
The compact coordinator fixtures are explicitly serialized within their suite
and allow enough event-loop turns for the asynchronous private-ledger reread;
this prevents a test-only reset race from masking the production boundary.

The post-audit focused run passes all 35 control-arbiter tests, including the
cross-wrapper replacement, cross-wrapper disable, single-flight flush, and
session-reload cancellation regressions. The combined real-session and planner
integration run passes 75/75. A fresh repository-wide offline verification then
passes 777/777 tests, typecheck, health, package smoke, optimizer verification,
and secret scan. These results supersede neither the older live hashes nor the
historical live receipt; a pinned smoke against the repaired loaded surface is
still required for G01-F revalidation.

## Limitations after G01 live validation

The historical live receipt predates the 2026-09-07 reload and single-flight
repairs. Until a fresh source/config/loaded-surface binding is produced, it is
evidence for the old surface only. The repaired source has no new live receipt.

The installed Pi version and direct compaction/recovery lifecycle are
characterized above. The Ling-tiny live requirement is satisfied. Qwen 35B has
a same-protocol supplemental receipt, but its print-mode teardown race is a
remaining portability limitation to address before treating non-interactive
continuations as universally reliable. Neither run provides model-quality or
adoption evidence.

The exact bounded command remains the G01-F preflight above; its pinned Pi
invocation is `/opt/homebrew/bin/pi -p --model
local-llamacpp/ling3-tiny-fast` with stdin redirected from `/dev/null`. The
accepted Qwen comparison used RPC because that mode keeps the host alive until
the second settled turn; the model and harness surface were otherwise the same.

The smoke must run only after a clean mirror/preflight has recorded the exact
source, configuration, and loaded-surface hashes. Its receipt must report the
exercised lifecycle transition and authenticated telemetry. It proves runtime
loading and the one transition exercised, not model quality or broad task
success.
