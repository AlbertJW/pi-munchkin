# SoL-Pi-Inspired Observation Archive: Feasibility and Plan

**Date:** 2026-09-24
**Status:** Planning only; runtime implementation and feature activation not authorized
**Harness baseline:** `main` at `d336a3257f34aa30ea60f50670b31ee95ca8d8c6`
**Hashline source surface:** `e8bf006093853a6da4b40eab16248b76da8c71810879f84f49ecb134224ed197`
**Installed SoL-Pi:** `1559b5cb12c72da4a485bc50fe326586b216fb19`; effective `~/.pi/agent/sol-pi.json` has `actionFusion`, `observationPack`, `evidencePreservingReducer`, and `onlineContextCompact` all `false`.

## Decision

Recommend **a minimal adaptation of the installed upstream ObservationPack**, not a second harness-owned archive and not unmodified activation of upstream. Keep the existing SoL-Pi installation and all four mechanisms disabled. If separately approved for implementation, adapt the branch-rewind counter lifecycle, recall-time digest/UTF-8 validation, and harness tool-activation integration; use upstream storage/projection/recall rather than duplicate those mechanisms. The installed implementation has a reproducible stale branch counter and does not revalidate full content at recall; the harness currently deactivates `obs_recall` under its core profile. Those seams make unmodified activation incomplete for the intended workflow.

The exact model-facing addition is one conditional tool, `obs_recall({ id: string, offset?: integer >= 0 })`, registered only when SoL-Pi `observationPack` is enabled and kept active by the harness while registered. This is a real schema/surface change; it must not be described as unchanged schemas. Do not implement Action Fusion, reducer inference, autonomous compaction, optimizer integration, or replay campaigns as part of the archive work.

### Branch-rewind reproduction

The code computes `priorAssistantCounts` from the current context history, but selects `sentCounts.get(sessionRoot + observationId) ?? priorAssistantCounts[index] ?? 0`. The in-memory map therefore takes precedence over active-branch history and is not cleared on `session_before_tree`/tree navigation. I ran a deterministic, isolated reproduction of that exact selection and counter update: first branch requests produced full, full, placeholder; after rewinding to history with zero assistant messages after the same observation ID, the same extension state still produced a placeholder, while a fresh extension at that rewound history produced full. This confirms the stale-map defect in the installed source.

The full extension-level test was not run: the installed checkout has no resolvable `@earendil-works/pi-tui` peer in its local node resolution, so direct import failed before the handler loaded. No package file was changed. Before implementation/activation, turn the source-level reproduction into a regression using the actual Pi `SessionManager` branch-tree API and `DefaultResourceLoader` under Pi 0.87.1; the deterministic result here is evidence of the algorithmic bug, not actual-host integration proof.

## Current harness comparison

| Area | Current behavior | Consequence for an observation archive |
|---|---|---|
| Read deduplication (`harness/lib/context-dedup.ts`) | Recomputes from the current context messages; pairs `read` calls/results and replaces later identical successful reads of the same path only when the reference is shorter. Errors and other tools are left alone. | Useful precedent for a deterministic context projection, but it neither stores content nor resolves an archive ID. It cannot recall arbitrary tool output. |
| Output guards | `bash-output-guard` is opt-in and converts oversized shell output to a bounded error result. The context-inlet guard limits risky/unbounded reads. | Archive only the final successful text actually eligible for context projection. Preserve errors and do not archive a guarded failure as if it were a complete observation. |
| Context accounting | Accounts the transformed provider payload; estimates remain estimates unless a provider-rendered exact counter is available. | Keep archive byte/hash metrics distinct from request accounting. A `/4` token heuristic is advisory; never label it verified or report it as measured savings. |
| Hashline 2.0 | `read(path, offset?, limit?)` returns numbered content and a full SHA-256 digest; `edit(input)` requires the digest of the current file bytes and rejects stale edits. Displayed line output is not a byte-exact archive transport. | An archived Hashline read is historical evidence, not authorization to edit the current file. Tell the model to perform a fresh `read` and use the current digest before editing. |
| Bounded read tools | `search_spans(path, pattern)` and `read_span(path, start_line, end_line)` provide bounded path-based search/read; `read_span` uses a short SHA-1 content tag and has no archive-ID or byte-offset semantics. | They are not substitutes for integrity-checked ObservationPack recall. |
| Compaction | Existing compaction tools and recovery brief manage context/session lifecycle separately. | Archive projection must not trigger compaction or modify compaction policy. It must survive compaction only through a valid archive reference and explicit recall behavior. |

Passing a filesystem path is not inherently unsafe. A path-based design can be safe if it is constrained to an approved session archive root and validates the expected object identity and digest. The current generic path read is nevertheless not equivalent to ObservationPack recall: its schema accepts a file path and line offset/limit, not an archive ID and byte offset; the harness inlet guard treats session/log paths as risky; generic read has no contract to compare the complete file against the placeholder's expected digest; and line-based paging plus response caps do not guarantee exact, UTF-8-safe continuation for arbitrary long lines. Hashline can supply a full digest for the *current archive file* but does not provide byte-page/EOF semantics and displays line-oriented content. `read_span` has only a short tag and no archive identity. `research_recall` in Ketch retrieves verified research notes, not arbitrary observations. No existing tool presently provides the combined identity, digest verification, bounded page continuation, explicit missing/corrupt state, and lifecycle guarantees required for transparent generic recall.

Thus generic path access is technically possible for some files, but does not currently establish safe, complete ObservationPack recall. A new tool is justified by the combined contract gap, not by a blanket prohibition on model-visible paths.

## Identity and data contract

Keep historical observation identity separate from current file identity:

* **Observation identity:** upstream derives `obs_` plus 24 hex characters from tool name, tool-call ID, and full content SHA-256. The object is then namespaced by the Pi session-derived archive root; the ID itself is not branch-bound. Retain that distinction: branch state controls when packing occurs, while the session root controls object lookup. The 24-hex ID is an index, not a substitute for validating the full expected content digest.
* **Current file identity:** Hashline's full SHA-256 over the current file bytes. It is independent of, and never inferred from, a historical observation ID or archived digest.
* **No stale edit authority:** a recalled observation may explain what a past read returned, but its historical Hashline tag must never authorize an edit. Editing requires a new current-file read and current digest.

The initial implementation should archive only successful, nonempty, plain-text results above a fixed byte threshold. Skip `isError`, partial/truncated, image/multimodal, empty, and structurally ambiguous results. SoL-Pi joins multiple text blocks with newline characters; that canonicalization can lose block structure. Either encode and hash a lossless supported representation or skip multi-block/multimodal results in the first version. Do not archive guard-generated errors or reducer/evidence receipts as ordinary observations.

## Projection order, evidence, and accounting

1. Existing tool-result guards and error transformations run as they do today. The archive must not turn an error into a successful result or archive a truncated output as complete.
2. Preserve Pi's session history. On the provider-context projection, let existing read deduplication and recovery-brief transforms run first. Place archive projection after those transformations and before final context-surface telemetry, then verify ordering under Pi 0.87.1's actual loader.
3. Store only eligible content in a session-scoped local object. Before replacing anything, verify the stored object against the full expected SHA-256. If writing, reading, or ledger publication fails while the full text remains in the event, fail open by retaining the original context result and emit bounded diagnostic status without raw content.
4. Replace eligible prior results with a bounded placeholder containing the opaque observation ID, original digest, byte/line counts, short excerpts, and exact recall instructions. Label excerpts as untrusted historical tool output. Never put raw prompts/model output into durable receipts.
5. Upstream already provides byte-offset paging, output caps, next-offset/EOF fields, no-follow opens, and regular-file checks. Its create/reuse path checks size and full hash, but `readRecallChunk` does not re-check the whole object's expected digest on each recall, does not establish an expected digest from the ID alone, and only trims an incomplete UTF-8 sequence at the page end; an arbitrary input offset inside a multibyte character is not repaired. The adaptation must persist trusted expected-hash metadata (for example, per-object metadata or a ledger index), validate the whole object before recall, reject invalid UTF-8 boundaries/offsets, and distinguish missing/corrupt data explicitly. Keep the existing `obs_recall` schema if this is done through session-scoped metadata; do not add parameters casually.
6. Context accounting measures the final provider payload after projection. Separately record original bytes, placeholder bytes, full content hash, and advisory token estimate. Do not claim verified token savings from a heuristic; compare actual before-provider payload accounting only where its own provenance supports that claim.

The archive should be fail-open for compaction/projection when the original text is still present, and fail-explicit for recall after the original is no longer available. Errors, partial outputs, and provenance metadata must remain visible as errors/evidence rather than being silently collapsed into placeholders.

## Session lifecycle, retention, and isolation

* Derive archive roots from Pi's session manager APIs; never use the process working directory or a user-supplied path. Keep objects isolated by session; do not claim branch-private storage. Do not let another session resolve an object by guessed ID.
* Fix the demonstrated branch-rewind state bug before activation. The smallest safe adaptation is to clear the extension's `sentCounts` map on Pi's `session_before_tree` event; a cancelled navigation may cause harmless extra full sends, whereas retaining a stale count can hide a still-needed observation. Confirm event ordering and cancellation behavior with Pi 0.87.1's real session tree. Resume starts a fresh extension map; forks must not resolve another session's archive root or inherit its in-memory counts.
* Upstream places objects below the session-derived root, so resume in that session can resolve them and forks with distinct session IDs get distinct object directories. Objects are not branch-private within a session: any branch that knows an ID can resolve it from that session's object store. The implementation and documentation must say session-scoped, not branch-isolated. On resume, verify object digests before emitting placeholders. If an object is missing or corrupt and source text is still in history, leave source text unmodified and record the archive as unavailable. If only the placeholder remains, recall must return an explicit missing/corrupt error.
* Restrict directories and objects (for example, 0700/0600), reject symlinks and path traversal, and treat archived text as untrusted content. The local archive contains potentially sensitive tool output; permissions do not provide encryption at rest.
* The inspected upstream has no independent object-retention/pruning policy; session-scoped object files can remain after a session ends as long as Pi retains that session directory. First adaptation should not add its own pruning mechanism. Document storage growth and rely on Pi's existing session-directory lifecycle; any later archive-specific pruning must be a separate design that proves it cannot delete objects needed by retained history.

## Tool activation and read-deduplication integration

SoL-Pi registers `obs_recall` only when its `observationPack` configuration flag is true. The harness `tool-activation.ts` core profile keeps only registered names in `CORE_NAMES`; `obs_recall` is currently absent there, and there is no observation capability family. Therefore, with the current core default, simply enabling upstream packing can leave its recall tool deferred/inactive even while placeholders are emitted. Smallest normal-profile integration: include `obs_recall` in the core-name allowlist. Because the tool only exists when the SoL-Pi feature registers it, this does not add it when ObservationPack is off; when on, it is immediately available without a second capability round trip. Explicit CLI/settings selections remain authoritative: when they exclude `obs_recall`, the packer must fail open and retain full results rather than bypass the user's restriction or emit unretrievable placeholders. Test feature-off/on, explicit exclusion, and manual deactivation.

Read deduplication is stateless and transforms only the context projection: the first identical successful `read` result remains, and later duplicates become small message-index back-references. The packer must run after deduplication. Its placeholder replaces content at the retained message's existing array index, so the dedup stub still points to that message; it must not remove/reorder messages. The stub is below the archive size threshold and should not itself be archived. The placeholder at the referenced earlier index must carry the `obs_recall` ID and instructions. If packing runs before deduplication, the transformed first read no longer hashes like the later original read and the dedup relationship is lost. Verify actual global/project extension ordering using Pi's loader and add an integration test for a repeated-read pair after the pack threshold.

The smallest future implementation is therefore the minimal upstream adaptation from option 2: retain the installed archive and exact `obs_recall({ id: string, offset?: integer >= 0 })` schema; reset stale send-count state on tree navigation; make `obs_recall` active in the normal core profile when registered, while not packing if explicit selection disables it; add persisted trusted metadata and recall-time integrity/UTF-8 checks; and enforce dedup-before-pack ordering. Keep all four SoL-Pi flags disabled until a separate execution approval. Do not add a second archive, parameters, inferred summaries, automatic compaction, or control-flow changes.

## Deterministic correctness validation

Before any benefit evaluation, add tests for:

* Threshold boundaries; successful pure text versus errors, empty, image/multimodal, partial, and guarded/truncated results.
* Exact canonical bytes and SHA-256; multi-block policy; Unicode/UTF-8 paging; full-send count and bounded placeholder size.
* Interaction with read deduplication, output guards, recovery brief, context-surface telemetry, and context accounting; confirm final provider payload is what accounting sees.
* Archive and ledger write failure; symlink/path traversal; missing object; corrupt object; digest mismatch; object size cap; session ownership; no raw content in durable receipts.
* Recall pages at start/middle/end, multibyte boundaries, exact digest, next offset, EOF, malformed offsets, and explicit corruption/missing errors.
* Session resume, fork isolation, `session_tree` rewind/replay, compaction/resume, and no stale in-memory send count.
* Hashline historical digest cannot authorize a current-file edit; re-read and current digest are required.
* Real Pi 0.87.1 loader/SDK startup and direct tool invocation without inference. Do not use copied extensions or native-tool doubles as actual-host compatibility evidence.

These tests establish deterministic correctness and integration behavior only; they do not establish that a model will recall or use the archived information correctly.

## Future benefit evaluation (separate approval required)

The primary question is the **total effect of enabling adapted ObservationPack in normal harness use**: baseline is the current harness with SoL-Pi installed but `observationPack=false`; treatment enables `observationPack` and makes the resulting `obs_recall` tool available, with branch-reset and ordering fixes. The treatment adds one tool schema and changes provider context, so this is explicitly a bundled treatment. Report the schema delta and do not claim schema parity or attribute an outcome solely to compression or recall.

Freeze a task set containing cases with large repeated observations and cases where later decisions depend on exact details from those observations. Keep exact model/provider, serving configuration, task prompt, context limits, environment, task order protocol, and judging fixed; randomize/counterbalance paired cells and blind independent judges to condition. Pre-register numeric quality non-inferiority and evidence-support margins, task completion criteria, tool-call/recall limits, latency and cost measures, sample size, exclusions, and incomplete/failure rules. Missing receipts are incomplete, not pass; corrupted/missing archive, unreachable recall, or unsupported factual claims are failures. Do not pool across models or serving configurations.

If a later study wants to isolate the effect of packing/retrieval from merely adding a tool schema, run a separately declared mechanism study with `obs_recall` registered and active in both arms: control has no packed objects and returns an explicit “no archived observation” result; treatment performs archive-backed recall. This estimates the effect conditional on equal tool exposure, not the production total effect. Do not silently mix these estimands or present the secondary control as ordinary current harness behavior.

Offline trace analysis can establish deterministic eligibility, transformed byte sizes, estimated token deltas, placeholder/page counts under a scripted policy, branch/session edge cases represented in saved traces, and whether the same archived bytes can be retrieved and verified. It cannot establish new model decisions, whether the model notices or correctly uses an archive, answer quality/completion after recall, extra inference turns, latency, or end-to-end benefit. Once a changed model decision or task outcome is part of the claim, fresh matched inference and independent evaluation are necessary and require separate approval.
