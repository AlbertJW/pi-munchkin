# G02 evidence — aggregate context admission per serving epoch

Status: implemented and producer-integrated; offline verification complete;
live model-switch smoke not run.

This package adds the `pi.context-accounting/v1` contract in
`harness/lib/context-accounting.ts` and the provider-payload admission observer
in `harness/extensions/context-admission.ts`. The observer partitions the exact
payload Pi is about to send into system instructions, tool schemas, retained
history, current user input, goal/recovery state, research cards, tool results,
working memory, and request metadata. Each partition is counted once and is
represented in diagnostics only by byte/token counts and SHA-256 digests.

Admission uses the active profile's effective served-or-declared window,
completion reserve, and overhead. Estimated token counts receive an explicit
uncertainty margin; an injected tokenizer is labelled exact/verified. A request
is admitted only when payload, uncertainty, outstanding reservations, overhead,
and completion reserve fit the window. Unknown windows and unaccountable
payloads fail closed. The extension aborts an unsafe provider operation without
rewriting or exposing the user payload.

`ContextReservationLedger` provides idempotent, epoch-scoped reservations for
concurrent retrieval and tool work. The admission extension publishes a
private `pi.context-reservation/v1` coordinator; Ketch search/read reserves its
bounded output before invoking the network adapter and the coordinator releases
it at Pi's tool-finalization boundary. A model/provider/endpoint/window change
invalidates older reservations. Recovery assembly uses
`preserveContextSections`, whose objective → constraints → active state →
evidence → next action → optional priority emits an explicit recoverable
truncation marker under the dark admission flag.

Targeted test evidence:

- `harness/tests/context-accounting.test.ts` covers contributor partitioning,
  exact-versus-estimated counts, reservation idempotence and shared budgets,
  preservation/truncation, provider/model/endpoint/window epoch binding, and
  fail-closed oversized-payload admission plus coordinator release (15 passing
  tests).
- `harness/tests/ketch.test.ts` proves a search reservation fails closed before
  the network adapter when the remaining aggregate budget is insufficient.
- `harness/tests/run-capsule.test.ts` proves admission-enabled recovery uses the
  bounded preservation contract without changing the legacy path.
- Existing context-profile tests continue to cover 32K/128K switching,
  endpoint identity, served-window shrinkage, one-shot handoff, rearming, and
  goal/non-goal continuation wording.

Offline verification completed on 2026-09-07: the full suite passes (782 tests),
typecheck passes, the package smoke loads all 31 extension entry points, the
optimizer verifier passes without inference, and the secret-diff scan is clean.

The package does not run inference, calibration, mirroring, or rollout. A live
receipt remains required for G02-F: an explicitly approved pinned-model switch
smoke must record actual usage and the handoff outcome. The admission observer
is opt-in behind `CONTEXT_ADMISSION=on` until that smoke is approved, so
existing defaults remain unchanged; it does not replace Goal 1 compaction
ownership.
